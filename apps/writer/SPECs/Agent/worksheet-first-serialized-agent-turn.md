## Invariants and ownership

- Rust owns the spawned process, ACP connection/session, and one process-wide active-turn coordinator keyed by the canonical Workspace path. The frontend submits an Agent id plus the discovery registration revision, never an arbitrary command. Rust reloads the current catalog/registration snapshot under its existing lock, rejects removed or revised custom selections, rebinds the executable on the blocking pool, and reruns the actual launch handshake/capability validation before `session/new`.
- Custom Agents are rebound to an immutable private native executable artifact before the turn and that artifact lives until process cleanup; the mutable registration path is never spawned.
- Every Writer window currently hosting the same canonical Workspace participates. Each participant snapshot includes the Rust `workspace_epoch` incarnation plus an unguessable participant token. Each prepare/reconcile request additionally has a phase-specific one-use request id; acknowledgements carry phase, turn, canonical root, epoch, participant/request ids, and the frontend lease `{generation,id}` acquired during prepare. Rust derives the label from the invoking Tauri window and rejects duplicate, wrong-phase, unsolicited, or superseded acknowledgements idempotently. The frontend retains a #10 lease only under that exact tuple, preventing same-root close/reopen ABA.
- Workspace publication and window destruction are coordinator-aware. A window cannot join an already-active Workspace; switching/closing withdraws its exact participant, and the turn is cancelled only when no matching participant remains. Publication is atomic with Writer mutation permits, and a blocked reconciliation slot is released once its final blocking participant withdraws. Delayed events from the withdrawn incarnation are rejected before preparation or ignored by the generation-bound frontend bridge.
- Prepare calls only #10 `prepareWorkspaceTurn`: acquire read-only then flush every open Document. Any save failure aborts before Agent spawn and all acquired leases are reconciled/released.
- The Rust coordinator rejects a second send while the Workspace is preparing, running, awaiting permission, or reconciling. The UI synchronously latches submission before IPC, disables send/Agent selection/conflicting registration actions, and exposes no queue.
- Terminal success, protocol failure, and runtime failure all enter explicit #10 reconciliation in every participating window before Rust releases the active slot and before the frontend reports the Workspace unlocked. Every window retains its #10 lease until all participants report successful reconciliation. A failed or timed-out acknowledgement produces a visible nonterminal `reconciliation-blocked` state; the active slot and lease remain blocked until the blocking participant is destroyed/withdrawn. Partial Agent writes remain on disk.
- ACP permission requests move the turn to `awaiting-permission`; the temporary Conversation displays the requested External Action and only `allow-once`/`reject-once` choices. Persistent choices are filtered and a request with no safe one-shot choice is cancelled. The invoking window submits one decision scoped to the exact turn/request/option, and Rust resumes the waiting SDK responder. Decisions remain temporary in this slice because durable Conversation history is a later ticket.
- AI Access Consent is persisted by canonical Workspace identity and never shared. Copy states that the Agent may use cloud services, may read/write the entire Workspace including ignored and non-Document files, and Writer cannot roll back changes.
- Assistant Conversation/message state is temporary frontend state for this slice. Its immutable owner is canonical root + frontend Workspace generation + temporary Conversation id + selected Agent id, extended with the turn id when assigned. Every consent/start/stream/permission/terminal result compares the captured owner and operation token; activation of any new generation resets it. One completed temporary Conversation remains terminal in this slice.
- One mount-once frontend event bridge must report listener readiness before send is enabled. It uses a disposed guard while asynchronous `listen()` calls settle, eventually unregisters every listener, reads the current root/generation at callback time, and rejects stale envelopes. Listener setup failure is visible and keeps sending unavailable.
- "Read-only" covers all Writer-owned Workspace mutation surfaces, not only TipTap. Sidebar create/rename/move/duplicate/delete actions are disabled and image/editor writes are suppressed. At the Rust boundary, a target-root-scoped permit is atomically coordinated with reservation and Workspace publication and remains held through actual blocking write/create/rename/delete/image I/O. The prepare flush is the only post-reservation Writer write and requires the exact participant/prepare-request identity. Navigation/copy/reveal remain available. This is application serialization, not an OS filesystem lock.
- Boundary work is finite: consent storage is versioned, count/file/path bounded, and atomically replaced; user prompts are at most 64 KiB UTF-8; one protocol line is at most 1 MiB; projected Agent text is at most 2 MiB; at most 128 change summaries of at most 4 KiB are retained. Prepare/reconcile waits are 60 seconds per phase, a permission decision waits at most 10 minutes, and a turn waits at most 30 minutes before cancellation/cleanup/reconciliation. Tests use injected shorter deadlines.
